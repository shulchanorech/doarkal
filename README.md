## עדכון גירסה של מסכתא

שם הקובץ נשאר תמיד `masechta.html` — כל גירסה חדשה פשוט מחליפה את הקודמת,
וההיסטוריה של כל הגירסאות נשמרת אוטומטית ב-Git (לשונית **History** / **Commits**).

**דרך האתר של GitHub:**
1. שנה את שם הקובץ החדש במחשב ל-`masechta.html`.
2. בדף הריפו: **Add file ← Upload files**, וגרור את הקובץ.
3. בתיבת ההודעה כתוב למשל `Phase 33` ולחץ **Commit changes**.

**דרך שורת הפקודה:**
```bash
git pull
cp /path/to/new-version.html masechta.html
git add masechta.html
git commit -m "Phase 33"
git push
```

לחזרה לגירסה קודמת: פתח את `masechta-full.html` ב-GitHub ← **History** ← בחר גירסה ← **View file** / **Raw**.

## אתר קל (פיצול הנתונים)

הקובץ המלא שוקל כ-23MB, ורובו נתונים. כדי שהאתר ייפתח מהר (גם בטלפון וגם מאחורי סינון), אחרי כל העלאה
רצה לבד הפעולה **Split data for Pages** (בלשונית **Actions**, תוך דקה-שתיים), ומשאירה במאגר:
- `masechta.html` — קובץ קל (פחות מ-1MB). הנתונים שלו נטענים מ-`data/` במקביל, כך שהספירה "(1/5)" מופיעה מיד.
- `masechta-full.html` — הקובץ המלא, בדיוק כפי שהיה עד עכשיו. הוא עובד גם כשפותחים אותו מהמחשב בלי אינטרנט.
- `data/` — קובץ לכל בלוק נתונים. בלוק שלא השתנה שומר על אותו קובץ, ולכן הגירסה הבאה מורידה רק מה שהשתנה.

**שגרת ההעלאה לא משתנה:** מעלים `masechta.html` כרגיל — קובץ מלא, או הקובץ הקל אחרי עריכה. שניהם עובדים,
והפעולה מסדרת את השאר. אין צורך לשנות שום הגדרה (Pages ממשיך לפרסם מ-`main` כמו קודם).
לעריכה כדאי להתחיל מ-`masechta-full.html` (הקובץ הקל לא נפתח מהמחשב, כי הנתונים שלו בקבצים נפרדים).
מי שעובד משורת הפקודה: `git pull` לפני כל עבודה, כי הפעולה מוסיפה commit אחרי כל העלאה.
אם הפעולה נכשלת (X אדום בלשונית Actions), האתר ממשיך להגיש את הקובץ שהועלה כמו שהוא — עובד, רק לאט יותר.
